# 对过度设计资源链路的思考
## 背景
在开发CaIEngine的时候走过最大的弯路应该就是对于资源工具链的设计。首先我的设计非常的浅显因为没法做深，能力有限。其次是过度设计，想当然的认为资源工具链需要非常复杂的设计来支撑未来的各种需求。结果导致了大量的时间浪费在设计和重构上面，最终还是回到了最简单的设计上面。

## 过度设计的表现
1. 本身简单的需求——将模型加载到内存中，但是现在使用复杂并且不完善的资源管线并没有任何收益，我认为应该将事情做到足够简单。
2. 并且我还引入了负优化的CPU缓存，我没有做任何的压缩，仅仅只是将内存的内容原封不动写入磁盘中，这样并没有带来什么好处，而且我使用JSON序列化资源结构，这导致资源加载并没有比raw的快。
3. 这样的资源加载缓存复用极大的增加了我的心智模型负担。

## 重新设计与反思
1. 资源工具链的设计应该以简单为主，满足当前需求即可，不要为了未来可能的需求而过度设计。
2. 资源就三个状态，磁盘一份，内存一份，GPU一份。磁盘上资源的格式应该尽可能的简单，内存中的数据结构也应该尽可能的简单，GPU中的数据结构也应该尽可能的简单。不要为了节省内存或者加载时间而设计复杂的数据结构。
3. 仅仅只是增加必要的结构性数据，比如带有Pass的Shader，就是精简版的SRP的实现。
4. 不做未来的设计，将现在的设计好即可，并且不耦合保证独立和拓展型以便不时之需。
